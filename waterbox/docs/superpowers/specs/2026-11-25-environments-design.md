# Waterbox environments — design

Status: approved; implemented on branch `environments` (v1.23).

## Goal

Let one host user own several independent boxes ("environments"), for example
one for AI agents and one for gaming. Each environment is a complete Waterbox
box: its own Arch rootfs, guest home, packages, shares, systemd machine and
network. Most sessions live in one environment; the others are occasional.

## Identity and storage

An environment has a fixed numeric **ID** (0–15) and a mutable **name**.

- The ID decides every host-side identifier. It never changes.
- The name is only a label shown and typed in the CLI. Renaming edits the label
  and nothing else, so it works while the environment is running.
- The root helper never sees names. It accepts only a validated ID.

| | env 0 (existing box) | env N (1–15) |
|---|---|---|
| Config dir | `~/.waterbox` | `~/.waterbox/envs/N` |
| Rootfs | `~/.waterbox/root` | `~/.waterbox/envs/N/root` |
| Machine / unit | `waterbox` / `waterbox.service` | `waterbox-N` / `waterbox-N.service` |
| Host iface | `ve-waterbox` | `ve-waterbox-N` |
| Subnet | `10.20.30.0/24` | `10.20.(30+N).0/24` |
| Resume marker | `/var/lib/waterbox/live-<uid>` | `/var/lib/waterbox/live-<uid>-N` |
| Autostart unit | `waterbox-autostart.service` | `waterbox-autostart-N.service` |

Env 0 keeps every current path and identifier, so an upgrade moves no data and
existing autostart units and wake timers keep working unchanged.

Per-environment files (inside its config dir): `root`, `shared_paths`,
`shared_paths.pending`, `gui_env`, `gui_binds`, `bootstrap-in-progress`.
Global files stay in `~/.waterbox`: `latest_version`, `completion.zsh`, and the
new registry `~/.waterbox/envs.list`.

Registry format: one `<id> <name>` line per environment. Names use the session
charset (`A-Za-z0-9._-`, no leading `-`, at most 64 chars) and are unique. The
registry is user-writable and trusted only by the ordinary-user CLI; nothing
privileged reads it.

Migration: when the registry is missing and `~/.waterbox/root` exists, the CLI
writes `0 main`. When neither exists (first ever run), it also writes `0 main`.

The containment rule is unchanged: `JAIL_ROOT` stays a literal path built from
the home and the ID, and `_in_jail` rejects anything resolving outside it. A
symlinked `envs/N` fails containment exactly as a symlinked `root` does today.

## Root helper

- New global `--env N` argument, parsed beside `--user`. Missing means `0`, so
  host units generated by older releases still target the original box.
- Validation: decimal `0`–`15`, no leading zeros. Anything else exits 2.
- From N the helper derives `MACHINE_NAME`, `JAIL_ROOT`, `WB_CFG`, `HOST_IP`,
  `CONTAINER_IP`, `VE_IFACE`, the resume marker and the autostart unit name.
  Every existing verb then runs unchanged against that environment.
- New verb `env-delete` (env ≥ 1 only, box must be stopped): removes the rootfs
  and config dir with the same root-owned deletion path `reset` uses, plus that
  env's resume marker, autostart unit and host wake timers. Env 0 is deleted
  through the same verb with its legacy paths; the global files survive.
- Host wake timers record `--env N` in their `ExecStart`. IDs stay global
  (`wake-1`, `wake-2`, …) so the list and delete commands are unchanged.
- `autostart-enable/disable` generate the unit for the given env.
- The unattended `flock` stays global: one unattended boot at a time.

### Shared resource cap

All environment units run in `waterbox.slice`. The helper writes a fixed
runtime unit `/run/systemd/system/waterbox.slice` (rewritten only when its body
changes, then `daemon-reload`) carrying the current limits:

```text
MemoryHigh=60%  MemoryMax=70%  MemorySwapMax=<10% of swap>
CPUWeight=50    IOWeight=50
```

Each environment unit keeps `TasksMax=2048` and `OOMPolicy=continue`. Memory,
CPU and I/O limits move from the unit to the slice, so all running environments
together stay within today's single-box limits. A slice write failure fails the
boot. Consequence, documented in AGENTS.md: under memory pressure the kernel may
OOM-kill a process in any running environment, not only the one using most.

`status` reads memory from the slice ("all environments") and tasks from the
selected environment's unit.

## CLI

### `waterbox env`

```text
waterbox env                        menu
waterbox env list                   name and state (running / stopped / not built)
waterbox env create <name>
waterbox env rename <old> <new>
waterbox env delete <name>
```

Menu: `Select an environment (↑/↓ move · Enter start · a new · r rename · d delete · q quit):`
built on the existing `choose_menu`. Rows: `<name>  [running|stopped|not built]`.

- **create** takes the lowest free ID and writes the registry line. It does not
  bootstrap; the first boot of that environment runs the existing bootstrap.
- **rename** validates the new name and rewrites the registry atomically
  (temp file + `mv`). Allowed while running.
- **delete** refuses while the environment runs. It prints what is destroyed
  (rootfs, guest home including agent logins and chat history, shares list,
  wakes, autostart) and requires typing the environment name. Host files behind
  shares are never touched. The registry line goes only after the helper
  reports success.

### Picking an environment for per-box commands

`stop`, `restart`, `status`, `reset`, `share`, `autostart`, `schedule-command`
and `wake-claude` accept `--env <name>` (global option, any position). Without
it:

1. only one environment exists: use it;
2. exactly one environment is running: use it;
3. on a TTY: open the environment menu;
4. otherwise: error asking for `--env`.

`status` without `--env` prints one summary line per environment, then the
shared slice resources.

### `waterbox start`

Session picker rows: `<session>  [<env name>]`, from every **running**
environment, sorted by environment then session.

- **Enter**: attach to that session in its environment. No environment prompt.
  Networking/DNS reassertion and the outdated-config check run for that env.
- **a**: environment menu, preselected on the environment of the highlighted
  session. Enter boots it if stopped (current `--gui/--x11/--no-gpu/--usb`
  flags apply to that boot), then the new-session name prompt.
- **r / d**: rename/kill the session inside its own environment, as today.
- No running session: open the environment menu directly. First ever run
  creates `main` first, so the menu shows that one row. After the boot, if
  restore brought sessions back, return to the session picker; otherwise prompt
  for the session name.
- `start <session>`: search running environments. One match attaches. Matches
  in several environments error and ask for `--env`. No match creates it in the
  environment picked by the rules above (`--env`, single env, or menu).
- `start --here`: shares the directory into the picked environment.
- `--env <name>` on `start` skips the environment menu and filters the session
  picker to that environment.

Session names stay unique only within one environment.

## Error handling

- Unknown `--env` name: error listing existing names.
- Env ID space full (16): `env create` errors.
- Boot failure in one environment never touches another: per-env markers,
  units, subnet and rules.
- Network cleanup is per interface/subnet and stays idempotent.

## Audio and gamepads (`--audio`, `--gamepad`)

Both are explicit per-boot flags on `start`/`restart`, like `--usb`: never on by
default, never persisted, never used by autostart or wake, and each prints a
warning stating the consequence when enabled.

### `--audio`

- Host requirement: PipeWire. The helper accepts only
  `/run/user/<host-uid>/pipewire-0`, a socket (not a symlink) owned by the host
  user, and ID-map-binds it to `/tmp/.waterbox-pipewire` (container uid 1000
  mapped to the host user, as for Wayland). No PipeWire socket: clear error,
  no fallback.
- The host Pulse socket is never exposed. A Pulse client can make the host
  server load modules (for example a TCP listener). Instead the box runs its
  own `pipewire-pulse` as the guest user, connected to the host graph through
  `PIPEWIRE_REMOTE`; modules loaded over Pulse load inside the box.
- Guest side: packages `pipewire pipewire-pulse pipewire-alsa` join `PKGS` for
  new builds. Existing boxes are never package-upgraded implicitly; when the
  binary is missing the shell prints the one-time install command.
  `/etc/waterbox/boot-env` (written by the helper from the accepted mount,
  never copied from a user file) exports `PIPEWIRE_REMOTE`. Managed guest config
  masks the box's own `pipewire.service`, `pipewire.socket` and
  `wireplumber.service` user units so no second graph starts, enables
  `pipewire-pulse.socket` globally, and a drop-in gives `pipewire-pulse.service`
  the remote plus `ConditionPathExists=/tmp/.waterbox-pipewire`.
- Warning: the box is an unrestricted PipeWire client: microphone, all audio,
  rerouting, and possibly code loaded by PipeWire's plugin factories as the host
  user. A restricted-access socket is the deferred proper fix.
- Environments never reach each other: one `FORWARD -i ve-waterbox+ -o
  ve-waterbox+ -j DROP` stays above every per-environment ACCEPT.

### `--gamepad`

- The helper selects nodes from the host udev database
  (`/run/udev/data/c<major>:<minor>`, root-owned host files):
  - `/dev/input/event*` with `ID_INPUT_JOYSTICK=1` and without
    `ID_INPUT_KEYBOARD=1`;
  - `/dev/input/js*`;
  - `/dev/hidraw*` whose HID parent device also owns a selected event node.
    Security keys and keyboard vendor interfaces therefore stay out.
- Each selected node gets its own `--bind` and its own exact-path
  `DeviceAllow` (never the `char-input` major), so unsafe mode cannot mknod a
  keyboard node.
- Access through the same ACL grant/revoke path as `--usb` (grant after a
  successful boot, failure stops the box, revoke on stop, skipped under the
  identity map).
- `/dev/uinput` is never passed: it would let the box create a virtual keyboard
  and type into the host session. Steam Input remapping/virtual pads do not
  work; native controller support does.
- In-box discovery: `/etc/waterbox/boot-env` (helper-written) exports
  `SDL_JOYSTICK_DISABLE_UDEV=1`, so SDL and Steam scan `/dev/input` directly.
  No udev database is synthesized.
- **Minor-number reuse guard.** The device cgroup and the bound inode both work
  by major:minor. When a pad is unplugged the kernel frees its minor, and the
  next input or hidraw device (a keyboard, a security key) may get the same one;
  the box's old bind and `DeviceAllow` would then reach that new device. A
  helper-run guard unit (`<machine>-devguard.service`, `BindsTo=` the box unit,
  `Restart=always`) follows `udevadm monitor` for `input`/`hidraw` removals and,
  when a passed node disappears, reapplies the box's `DeviceAllow` list without
  it through `systemctl set-property --runtime`. The base list is kept by the
  helper in root-only `/run/waterbox/devallow-<uid>-<env>`.
- Only controllers present at boot. A pad connected later needs a restart.
- A host seat change (fast user switching) may reset device ACLs; restart with
  `--gamepad` afterwards.
- Warning: the box reads every input of the passed controllers and can drive
  their rumble/LEDs/firmware interfaces through hidraw.

## Out of scope (follow-ups)

- Ctrl-b s inside a box lists only that box's sessions.
- Per-environment memory budgets.
- Copying or cloning an environment.

## Testing

- Extend `tests/test-waterbox.sh`: registry migration, name validation, rename,
  env picking rules, `--env` grammar and arity, helper `--env` validation and
  derived identifiers (env 0 identical to today), slice unit body, wake/autostart

  autostart and wake for env N; restore after hard power-off for both; delete.
